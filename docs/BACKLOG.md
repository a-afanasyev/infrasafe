# Единый беклог InfraSafe

**Сведён 2026-08-10.** Отменяет как самостоятельные источники:

- `AUDIT_REPORT.md` (6 августа) — ID вида `AR-` / `CO-` / `DE-` / `SE-` / `EN-`
- `docs/audit/sprint-11-backlog.md` (25 июля) — ID вида `M-` / `R2-` / `L-` / `B-` / `AUD-`

`sprint-11-backlog.md` остаётся в репозитории как доказательная база. С
`AUDIT_REPORT.md` иначе: он в `.gitignore` (строка 129) как «вывод скилла
`/audit`, перегенерируется каждый прогон, хранится локально» — то есть **никогда
не был закоммичен**. Августовские находки живут только на машине, где запускался
аудит, и исчезнут вместе с ней.

Поэтому здесь у каждого пункта есть не только ссылка, но и описание сути:
файл должен быть самодостаточным, а не оглавлением к чему-то, чего в репозитории
нет. Обоснования и разбор по-прежнему стоит смотреть в исходных отчётах, если
они под рукой.

## Зачем сведение

Не потому, что списки дублируют друг друга. Августовский аудит читал июльский
заранее, намеренно не переописывал его открытые пункты и взял непересекающееся
пространство идентификаторов — это сказано в его шапке и выдержано. Немногие
совпадения (`AR-8` ↔ `M-2`/`B-003`, `EN-6` ↔ `R2-37`, `AR-3(б)` ↔ `R2-04`/`AUD-008`)
он сам и помечает ссылками на старые ID.

Проблема в другом: **открытое множество не лежит целиком нигде**.

- Июльский список не обновлялся с 25 июля. Шесть его пунктов закрыты августовской
  и последующей работой, и там это не отмечено — список завышает объём.
- Августовский отчёт по построению содержит только новое, то есть заведомо неполон
  как рабочая очередь: двадцать шесть июльских пунктов в него не входят по замыслу.
- Ни один из двух не знает про приоритеты другого. «P1» августовского и «P1»
  июльского — разные шкалы, сравнить их можно только вручную.

Поэтому здесь не третий аудит, а сложение двух с перепроверкой каждой ссылки
и единой шкалой приоритета. Новых находок в этом файле нет — кроме одной
пометки про `sendSuccess`, всплывшей при сверке.

**Почему AR-17 снят.** Формулировка «агрегирующий запрос на каждый сэмпл»
звучит тревожно, но запрос идёт по индексу `idx_metrics_ctrl_ts`
(`controller_id, timestamp DESC`) в окне 600 секунд — это около десяти строк.
Замер `EXPLAIN (ANALYZE, BUFFERS)` на живой базе: **0.18 мс, один буфер**.
При целевых 200 контроллерах × 1/мин это 3.3 вызова в секунду, то есть порядка
0.06 % одного ядра.

Важнее, что очевидная «оптимизация» здесь вредна: взводить cooldown на здоровом
сэмпле прямо запрещено — так маскируется persistence-гейт, и этот урок уже
оплачен коммитом `e15436f`. Писать код ради 0.18 мс, рискуя вернуть закрытый
дефект, — плохая сделка.

## Контекст: что вообще под нагрузкой

Беклог взвешивался по риску в коде. Вот что на площадках на 10 августа:

| | profk | .105 |
|---|---|---|
| здания | 30 | 8 |
| трансформаторы | **0** | 4 |

На главной площадке живёт только интеграция с УК. Энергетическая часть —
представление, аналитика нагрузки, проверки напряжения, определение offline —
обслуживает пустой набор данных. Четыре пункта (`AR-6`, `AR-8`, `AR-20`, `DE-7`) описывают код, который сегодня
не может сработать по отсутствию входных данных.

менее срочными, а более — они привязаны к дате подключения железа. Оба закрыты
волной E: первый кодом, второй замером, показавшим, что проблемы нет.

`AR-3(б)` + `Новое №8` **одним PR**, порядок внутри жёсткий: сперва разбор статуса
в catch, затем перевод на модели. Иначе типизированные 4xx моделей окажутся
проглочены. Попутно снимается `AR-3(в)` — `adminQueryBuilder` остаётся только под
листинги. Закрывает три ID из двух источников сразу.

### ✅ Волна C — валидация, пачка S-размера (PR #186)

`CO-7`, `L-6`, `L-7` закрыты; `AR-11` — половина (`retryLog`). Общая тема:
вход не проверялся там, где должен, и отказ приходил как 500 вместо 4xx.
Правильные образцы для всех четырёх нашлись в самом репозитории — это был
перенос дисциплины, а не изобретение.

Побочно: whitelist статуса контроллера поставлен на ВСЕ ТРИ пути записи, а не
только на `create` (приём M-12), и модель перестала глушить собственную 400 в
500. Найден счётчик `active_controllers_count`, который всегда ноль — заведён
отдельным пунктом со сроком.
