## 1. Executive summary

1. Общее состояние хорошее: циклических зависимостей нет, default-deny авторизация, HMAC-пути, outbox, воркеры с advisory-локами и тесты на живом Postgres сделаны зрело. **P0 нет.**
2. **Главный функциональный дефект (N-01, P1):** все маршруты `GET/PUT/DELETE /:id` источников тепла и холодной воды валидируют `id` как целое, а ключ в схеме — `varchar(50)` (`'HS-FARABI-01'`, `randomUUID()`). Админка не может открыть, изменить или удалить ни один источник; регрессия пришла с R2-16 (`f46f4743`), тестов на эти пути нет.
3. **Схема БД (N-02, P1):** базовый `docker-compose.unified.yml` (профиль infrasafe.uz) бутстрапит том из устаревшего `database.sql` (без 011–034, без манифеста), и автоматической сверки схемы «чистый bootstrap + migrate up» с продами нет. Аварийное восстановление infrasafe.uz по штатному compose упрётся в fail-close раннера.
4. **2FA (N-03, P2):** промахи второго фактора не считаются на аккаунт — только 10/15 мин на IP, temp-токен не гасится; плюс мелкие дефекты того же модуля (обход anti-replay пробелом, неатомарное погашение recovery-кодов, 500 вместо 400).
5. **Надёжность алертинга (N-05…N-07):** занятый advisory-лок считается отказом БД и может открыть общий breaker AlertsDB на 60 с; повтор resolve в reconcile закрывает многодомный алерт без проверки остальных заявок; ошибка БД в сверяющем проходе A-03 навсегда помечает сироту как «без адресата».
6. **Остатки свежих фиксов на фронте (N-08, N-09):** форма создания здания шлёт `hot_water` вместо `has_hot_water` (флаг ГВС теряется → отказ ГВС не видно на карте); DTO метрик превращает измеренный `0` в `null`.
7. **Доверие периметра (N-04, P2):** SPA и API УК живут под тем же origin, что InfraSafe; XSS на стороне УК = полная сессия админа InfraSafe. Требует координации с УК.
8. **Простота:** ~900 строк runtime без потребителя (batch-маршруты, runtime-пороги с ложным контрактом, неподключённый refresh в браузере, мёртвые методы), 79% строк `src/routes` — swagger-JSDoc, 17 МБ `trash/` в индексе git при том, что бэклог считает его убранным.
9. Практики сильные (SHA-пиннинг actions, Trivy, gitleaks, CodeQL, фазовый откат деплоя), но: gitleaks исключает все `docs/*.md`, `nginx:alpine` без мажорной версии, у workflow нет `permissions:`, CI-порог `npm audit` (`high`) пропускает runtime-уязвимость `qs`.
